# ADR-0006: Local IPC: length-prefixed JSON over a verified, user-only socket or named pipe

Status: accepted (approved by the owner on 2026-11-18)

**Context.** The UI host, the command-line tool and the sync agent all need the service, and the UI host needs the sync agent. Messages are small and infrequent (the key path does not cross a process). A local endpoint name is not secret, so another process could create it first and impersonate the server.

**Decision.** A Unix domain socket (macOS, Linux) or named pipe (Windows). Servers create the endpoint exclusively (first pipe instance; socket in a `0700` directory they own), restrict it to the current user, reject remote pipe clients, and refuse to start if the name is taken. Both sides verify the peer before sending anything: same user, and in release builds the installed, signed Iamb executable. Frames are a 4-byte little-endian length plus a JSON document (at most 8 MB); bulk data travels as file paths. Requests carry an id; servers also push events. The first message is a versioned `Hello` stating the client role, and each role may call only its own message groups. Message bodies are never logged. `iamb-ipc` is blocking-only.

**Consequences.** The contract can be checked with golden files, and JSON costs microseconds at this volume. A sync agent bug cannot read diagnostics or pause the engine. A squatting process gets a refusal, not credentials or form values.

**Rejected.** A binary format (no measurable gain, harder to test). Local HTTP or WebSocket on a TCP port (reachable by other users and by web pages; needs a network stack in the service). A general RPC framework (large dependency in the process that sees keystrokes). Trusting the endpoint's access-control list alone (does not stop squatting, and on Windows admits the same user from another machine).
