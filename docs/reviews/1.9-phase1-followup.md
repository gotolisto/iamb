stepping, 800,000 templates in 100,000 random libraries compile the same shared as alone, and

problem beyond N1, four new medium ones (N1 aside): the migration is quadratic (49 s for a

rule, and a held form submit can delete text in another application after a second focus change;
the rest are low. Phase 1 can be signed off once N1 and N2 are fixed and N3 and N4 are fixed or
accepted by the owner.

## 3. New findings

Severity as in the first review: high = wrong behaviour a user would hit, data loss, privacy
leak, or a crash or hang reachable from input; medium = spec deviation or missing test for
important behaviour; low = clarity, robustness, minor.

### N1. Snapshot build is still quadratic when a form cannot be shared — high, demonstrated (the open part of finding 2)

- Where: `crates/iamb-core/src/template/resolve.rs:178-216` (`form_of`, `sole_form_child`) and
  `:403-420` (`build_form`).
- What: a template shares an included body's form only when it has no `{field}` or `{if}` of its
  own and exactly one included body with fields. Otherwise it gets its own complete copy of every
  field below it. Parsed bodies are shared in every case; the forms are what is copied.
- Shown by: n leaves with one field each, one hub that includes them, n snippets
  `Dear {field name=who}, {snippet abbr=hub}`:

  | Snippets | Review's shape (no own field) | One own field each |
  | --- | --- | --- |
  | 501 | under 0.01 s, +1 MiB | 0.03 s, +16 MiB |
  | 1,001 | under 0.01 s, +2 MiB | 0.09 s, +46 MiB |
  | 2,001 | 0.01 s, +3 MiB | 0.35 s, +179 MiB |
  | 4,001 | 0.02 s, +6 MiB | 1.63 s, +709 MiB |
  | 10,001 | 0.05 s, +28 MiB | 10.6 s, +5,535 MiB |

  The same figures result from an own `{if}` (1.65 s, +709 MiB at 4,001) and from two hubs with no
  own field (1.81 s, +708 MiB at 4,002).
- Why high: it is the same exposure the first review rated high. The build runs on every snapshot
  rebuild and in every `iamb expand`, and the content can come from a shared folder. It needs a
  form with thousands of fields, which no honest library has (200 fields: 0.01 s, 7 MiB), so only
  a hostile or broken library reaches it; the owner may prefer to close it with a limit.
- Fix: either limit the number of fields of one form (a resolve error, which needs a line in the
  template spec), or let a form link to the forms of included bodies instead of copying their
  fields. Add the own-field shape to `shared_hub_library_builds_in_linear_time`.

### N2. Migration 2 is quadratic and runs inside `Store::open` — medium, demonstrated

- Where: `crates/iamb-store/migrations/0002_fold_final_sigma.sql` (the `NOT EXISTS` compares
  `replace(...)` of both keys, so no index helps: every row with a final sigma scans every live
  row of its profile); `crates/iamb-store/src/migrations.rs:97-109`.
- Shown by: version 1 databases with live snippets in one profile whose keys contain `ς`
  (abbreviations such as `λογος`), first `Store::open`: 10,000 rows 49 s; 20,000 rows 205 s. The
  same 10,000 rows without the letter: 0.01 s. The second open takes 1 ms.
- Effect: for that time the store lock is held, so `iamb` gives up after 3 s and a worker after
  5 s (architecture §6.3). A migration that is interrupted rolls back and starts again from the
  beginning; if the supervisor's 3-second heartbeat rule (§3.2) applies while the worker opens
  the store, it never finishes. That last part is suspected, not demonstrated: the service does
  not exist yet.
- The rewrite itself is correct (row 12), and a failing migration cannot be produced by the
  collision rule: no row is ever updated to a key another live row holds, before or after the
  statement.
- Fix now, because migrations are not edited once released: compute the new keys once into a
  temporary table, index it, and update the rows whose new key is unique in their profile. Add a
  10,000-row case with a time bound to `tests/migrations.rs`.

### N3. The form-value rule is in the spec text and the engine, but not in the reference implementation or the examples — medium, demonstrated

- Where: `docs/template-language.md:214-216` (new text), `spec/template/reference.py:463` (values
  used as given), `spec/template/examples/` (still 166 examples, none with a value that does not
  fit).
- Shown by: 20,000 generated templates with form values, engine against the shipped reference:
  201 differ, all of this kind (`{field name=a}` with value `a\r\nb`: reference `a\nb`, engine
  `a b`). With the three corrections added to a copy of the reference, 120,000 cases agree. The
  10,000 cases without values agree with the shipped reference.
- Effect: the examples are the contract for other implementations (the test strategy names the
  mobile bindings); the rule is untested for them and the reference now contradicts the spec.
- Fix: apply the rule in `reference.py` and add examples for the three cases (`choice` outside
  the options, `toggle` other than `yes` including an `{if … is=…}`, line break in `text`).

### N4. A held request survives a second focus change and runs in the next application — medium, demonstrated in the engine

- Where: `crates/iamb-core/src/engine.rs:324-329` (`FocusChanged` keeps `held`), `:341-343`.
- What: ADR-0024 and §4.5 say a request waits for "the focus thread's verdict". The engine keeps
  it across any number of focus changes and runs it on the first `normal` verdict, whichever
  application that is for. For a form that was opened by typing, the expansion starts with
  `DeleteBack(n)`.
- Shown by: `pw ` typed in app "a" opens the form; focus returns to "a"; `FormSubmitted` is held;
  `FocusChanged("b")`; `SecureState(normal)` → `DeleteBack(3)`, `TypeText "1234"`, `TypeText " "`:
  three characters of whatever is in "b" are deleted. The engine has no event that cancels a held
  request except `Overflow`.
- This does not reopen the owner's rule (only normal fields are typed into); it is about which
  window. How often it can happen depends on the service: the window is the time between the UI
  host handing focus back and the verdict.
- Fix: remember the application when a request is held (for a form, the application at the
  match); a `FocusChanged` that names another one drops the request with `RequestCancelled`.
  State the rule in §4.5.

### N5. Reuse of folders and tags by name on JSON import has no test that needs it — low, demonstrated

- Where: `crates/iamb-store/tests/transfer.rs:688` and `:751`;
  `crates/iamb-store/src/transfer.rs` (`existing.by_key.get`, `live_tags.get`).
- What: the re-import test passes because an import that skips every snippet creates nothing.
  With the reuse of folders, or of tags, switched off, all 13 transfer tests still pass.
- The behaviour is right today: importing a file that adds one snippet to `Work / Email` reports
  "1 snippets (2 skipped), 0 folders and 0 tags created".
- Fix: a test that imports a file with one new snippet in an existing folder and with an existing
  tag, and counts folders and tags.

### N6. A pair the migration leaves alone cannot be edited — low, demonstrated

- Where: migration 2's collision rule; `crates/iamb-store/src/entity.rs:561`.
- What: for live `ος` and `οσ` in one profile the first keeps its old key. After that, changing
  its label or disabling it fails with "abbreviation "οσ" is already used by snippet …"; the
  other row can be edited, and either can be deleted or renamed. Nothing tells the user after the
  upgrade (library health is not built yet), and ADR-0024's "the store can never accept two
  abbreviations the matcher treats as one" does not hold for such a pair.
- Fix: say so in ADR-0024 and list such pairs in library health; or let `put` accept an unchanged
  abbreviation whatever its stored key.

### N7. Explicit requests depend on event order the architecture does not fix — low, suspected (design)

- Where: `crates/iamb-core/src/engine.rs:632-662`; architecture §4.5.
- What: (a) a submit or pick that reaches the engine before the `FocusChanged` for the returned
  focus finds the verdict `own_window` and is refused at once (shown: `refused_own_window`; the
  values are kept and `ReopenLastForm` works). The request comes over IPC and the focus event
  from the focus thread, so the order is not given. (b) A newer request that is refused for
  composition does not replace the held one, which then runs (shown: pick A held, pick B refused,
  A typed). (c) `FormCancelled` for a session whose submit is held answers `unknown_form_session`
  and the submit still runs.
- Fix: decide in §4.5 who orders the events (for example the service sends the focus change for
  the token's window before it forwards the request), and whether a refused request cancels a
  held one.

### N8. The architecture contradicts itself after the amendment — low, demonstrated

- §8 rule 1 says typed characters exist only in the engine's buffer; §4.6 now puts a second copy
  in the listener. Rule 1 has to be amended (and ADR-0012 with it), since the Phase 2 privacy
  review checks §8.
- §8 rules 1 and 9 and the title and text of ADR-0012 still say 64 characters; ADR-0012 and
  ADR-0013 do not point to ADR-0024.
- §4.1 says the engine's allocation "holds the buffer inline"; `Engine` holds `Box<KeyBuffer>`

- §8 rule 4 says a diagnostic made while suspended names only the app and the reason; the new

- `docs/ci.md` does not mention the coverage job or the nightly workflow.

## 5. How the fixes were tested, and what showed no problem

- **Business days.** Closed form against stepping one day at a time through the public API, both
  signs, at both ends of the year range (row 1). Also through the reference comparison below,
  with `now` at 0001-01-01, 0001-01-05, 9999-12-29 and 9999-12-31.
- **Shared bodies and forms.** One compiler is made per snapshot build and nothing is kept between
  builds (no static or cached state in `iamb-core`), so an edit to the library cannot leave a
  stale body: the next snapshot parses everything again, and an open form keeps the snapshot it
  was matched in. For 100,000 random libraries of 2 to 14 snippets (random links, forward-only
  chains deeper than the limit of 8, hubs; cycles, missing snippets, parse errors, conflicting
  and undefined fields), built in shuffled order, each of the 800,000 templates compiled in the
  snapshot was compared with a resolve on its own: same error with the same snippet and position
  (about 400,000 errors, 17,000 of them `E_TOO_DEEP`), same form in the same order, same
  clipboard and cursor flags, same rendered actions. 0 differences.
- **Reference comparison.** 120,000 generated templates with up to 11 nested snippets, half of
  them compiled through `Snapshot::build`: error code, actions, form and `cursor_back` agree with
  the reference implementation once it has the form-value rule (N3).
- **Held requests.** Every transition was driven by hand: hold before the first verdict and after
  a focus change; run on `normal`; refuse on `secure`, `excluded`, `unknown`, `own_window` and
  while composing; replace by a newer request; cancel on `Overflow`; a held request with an
  expansion in flight (refused with `injection_busy` at the verdict, flight untouched); a held
  pick across `SnapshotChanged` (runs the new body, or `unknown_snippet` if the snippet is gone);
  a held submit keeps the snapshot of its match; `forget_form_values` drops a held submit. Apart
  from N4 and N7 the behaviour is what §4.5 and the module docs say.
- **Buffer.** 66 characters; a 64-character abbreviation with word start fires after a boundary
  and not mid-word, also after 200 earlier characters; after 300 characters and 66 Backspaces a
  word-start abbreviation does not fire.
- **Migration 2.** The SQL rewrite equals the new fold for every key the old rule could produce
  (the two rules differ only in final sigma). 300 random databases (row 12). A newer schema is
  still refused, and each migration is one transaction.
- **CSV.** Random round trips (row 11); the reader does not trim cells, so escaped edge spaces
  survive.
- **File modes and durability.** Row 16 and 17; `-wal` and `-shm` take the database's mode.
- **Workflows.** Read and, where possible, run: coverage gate exit codes, the fuzz command, the
  mutation command and its gate script on real output, both bench commands.
