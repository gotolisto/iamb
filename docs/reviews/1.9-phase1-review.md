# Phase 1 review (task 1.9)

Date: 2026-11-18 · Commit reviewed: `24067dd` · Reviewer: independent, did not write the code

Scope: `iamb-core`, `iamb-store`, `iamb-cli`, `iamb-testkit`, `iamb-bench`, `fuzz/`, judged against
`docs/architecture.md`, `docs/template-language.md` with its examples, the decision records and
`docs/test-strategy.md`. No tracked file was changed. Probe programs and logs were kept outside
the tree.

## 1. Verdict

Phase 1 is functionally sound and well tested, but it is not ready to sign off. Every delivery KPI
I could re-measure passes with a wide margin, the template engine agreed with the reference
implementation on 130,000 random templates, the mutation score of the matcher is 99%, and I found
no path by which typed characters, form values or clipboard text reach a `Debug`, `Display`, log,
serialised form, error message or the store. Two findings are high: a small snippet can make one
render take seconds on the typing path (finding 1), and building a snapshot is quadratic in time
and memory for libraries that share nested snippets (finding 2). Both are reachable from library
content that other people can write, so they should be fixed before Phase 2 builds the service on
top. Eight medium findings are spec deviations or gaps in the delivery gates; the rest are low.

## 3. Findings

Severity: high = wrong behaviour a user would hit, data loss, privacy leak, or a crash or hang
reachable from input; medium = spec deviation or missing test for important behaviour; low =
clarity, robustness, minor. Status says whether I reproduced it.

### 1. A `{date}` shift with business days makes one render take seconds — high, demonstrated

- Where: `crates/iamb-core/src/datetime.rs:393` (one loop step per business day),
  `datetime.rs:354` (no limit on the number of shift terms),
  `crates/iamb-core/src/template/render.rs:346`. `MAX_RENDER_STEPS` counts nodes, not this work.
- What: `+9999bd` walks about 14,000 days one at a time, and a shift may hold any number of terms.
  Rendering runs on the engine thread at the moment of the match. A snippet with `{date}` from
  another member is not held for review (architecture §8 rule 10), so one shared single-line
  snippet can stall the worker past the 3-second heartbeat every time it is typed.
- Shown by: `{date shift="+9999bd -9999bd …"}` renders in 0.046 s with 100 terms (814 bytes),
  0.46 s with 1,000 terms (8 KB), 4.6 s with 10,000 terms (80 KB) and 23 s with 50,000 terms.
  A 5 KB template of 250 × `{date shift=+9999bd}` renders in 115 ms against the 1 ms target.
  Through the release binary: `iamb expand "slow "` took 4.69 s for the 80 KB body; a plain
  snippet took 0.003 s.
- Fix: compute business days arithmetically (whole weeks, then at most 4 single steps); cap the
  number of terms per shift (for example 16) as `E_BAD_SHIFT`, which needs a line in the template
  spec; add a test that a worst-case 5 KB template renders within the budget; run the fuzz target
  with `-timeout=1`.

### 2. Snapshot build is quadratic in time and memory when snippets share nested snippets — high, demonstrated

- Where: `crates/iamb-core/src/engine/snapshot.rs:134-148` (every snippet is resolved on its own),
  `crates/iamb-core/src/template/resolve.rs:92` (each resolve parses its own copy of every body
  below it), `crates/iamb-core/src/template.rs:358` (`Resolved` owns those copies).
- What: bodies are shared inside one resolve but not between snippets. A library where many
  snippets include one snippet that includes many others costs (users × included bodies) parses
  and keeps all of them in memory. This runs on every snapshot rebuild and in every
  `iamb expand`.
- Shown by: n leaf snippets, one hub that includes all of them, n snippets that include the hub.
  501 snippets: 0.10 s, +51 MiB. 1,001: 0.28 s, +152 MiB. 2,001: 1.08 s, +606 MiB. 4,001:
  4.81 s, +2,420 MiB. Control, 10,000 plain snippets: 0.016 s, no visible growth. At 10,000
  snippets of this shape the process would need roughly 15 GiB.
- Fix: parse each body once per snapshot and share it (`Arc<Body>` keyed by snippet), memoise
  height, form events and resolve errors per body, and let each `Resolved` hold links, not copies.
  Add a snapshot-build test with this shape and a memory or time bound.

### 3. `{clipboard trim=yes}` repeated through nested snippets makes one render take minutes — medium, demonstrated

- Where: `crates/iamb-core/src/template/render.rs:280-292`.
- What: every `{clipboard}` node clones the normalised clipboard when it contained a CR and scans
  it again to trim. When trimming leaves little or nothing, the output limit never stops the
  render, so the cost is nodes × clipboard size, up to 300,000 nodes.
- Shown by: clipboard of 64 KiB (CRLF, one letter, the rest spaces): 10,000 nodes take 0.81 s;
  250,000 nodes (three small snippets, 50 × 50 × 100) take 20.8 s; with a 1 MiB clipboard
  350 s. The 250,000-node renders end in `E_OUTPUT_TOO_LARGE`, but only after walking every
  node, because the character limit is checked at the end of the render.
- Rated medium, not high, because it needs both such a snippet and such a clipboard.
- Fix: normalise and trim the clipboard once per render and reuse both strings; count bytes
  scanned, not only bytes typed, against a render budget.

### 4. A snippet with a resolve error never matches, so typing it gives no diagnostic — medium, demonstrated

- Where: `crates/iamb-core/src/engine/snapshot.rs:153-165`; worked around in
  `crates/iamb-cli/src/expand.rs:179`.
- Spec: architecture §4.4 defines the matchable set as the enabled snippets "whose templates have
  no parse error"; template spec §5 says an expansion that fails logs the snippet and the code.
- What: snippets with `E_SNIPPET_NOT_FOUND`, `E_SNIPPET_CYCLE`, `E_FIELD_CONFLICT`,
  `E_FIELD_UNDEFINED` or `E_TOO_DEEP` are removed from matching together with parse errors. The
  "why didn't it expand" log stays empty, and a shorter abbreviation can fire in their place.
- Shown by: body `{snippet abbr="nowhere"}`, typed `lost ` → 0 actions; the same snippet through
  `ExpandRequest` → `Diagnostic E_SNIPPET_NOT_FOUND`. With a second delimiter snippet `ost`
  (word start off), typing `lost ` expands `ost` and leaves `lSHORTER `. Session
  `054_parse_errors_excluded.toml` asserts the silence.
- Fix: keep resolve-error snippets matchable and let `Engine::start` emit the diagnostic (the code
  path exists); or change the spec. Then drop the workaround in the command-line tool.

### 5. Palette requests and form submits are served while the engine is suspended, including a delete into a secure field — medium, demonstrated (behaviour); needs an owner decision

- Where: `crates/iamb-core/src/engine.rs:553-583` and `609-657`: no suspension check on
  `ExpandRequest`, `FormSubmitted`, `ReopenLastForm`.
- Spec: architecture §4.1 "engine suspended unless `normal`", §7 "apps where Iamb does not expand
  or buffer", §8 rule 7. The spec does not say that explicit requests are exempt; the module docs
  and sessions 048 and 099 decide that they are.
- Shown by: abbreviation typed in app "editor", form opens, focus moves to "bank-login" with
  verdict `secure`, then `FormSubmitted` → `DeleteBack(3)`, `TypeText "1234"`, `TypeText " "`.
  `ExpandRequest` also expands with verdict `excluded`, `unknown`, and while paused.
- Fix (if the owner agrees): remember the app at match time in the form session; on submit, if
  the focused app differs or the verdict is `secure`, `excluded` or `unknown`, drop the expansion
  with a diagnostic, or at least never emit `DeleteBack`. Refuse palette requests in excluded
  apps. Record the decision in ADR-0013 either way.

### 6. A 64-character delimiter abbreviation with word start fires only at the very start of the buffer — medium, demonstrated

- Where: `crates/iamb-core/src/matcher/buffer.rs:8` (capacity 65),
  `crates/iamb-core/src/matcher.rs:420`.
- What: 64 characters plus the delimiter fill the buffer, so the character before the abbreviation
  has fallen off and the matcher refuses. Delimiter mode with word start is the default, so a
  maximum-length abbreviation works only directly after a click, Enter or focus change. The spec
  allows 64 characters without this exception.
- Shown by: `dry_run` with a 64-character abbreviation: typed alone → expands; typed after
  `ok ` → 0 actions; a 63-character one after `ok ` → expands. The test
  `delimiter_64_char_abbreviation_and_truncation_fail_closed` (`tests/matcher_rules.rs:430`)
  asserts the failure, and the property test's reference model copies the same rule.
- Fix: make the buffer 66 characters (one before, 64, one delimiter) and update architecture §4.1,
  which still says 64.

### 7. Importing a JSON file again duplicates every folder and tag — medium, demonstrated

- Where: `crates/iamb-store/src/transfer.rs:845-873`.
- What: JSON import always creates the file's folders and tags, even when every snippet is
  skipped as a conflict. CSV import reuses folders and tags by name.
- Shown by: `iamb export lib.json`, then `iamb import lib.json` twice on a library with 3 folders:
  each run reports "0 snippets (2 skipped), 3 folders … created"; the store then holds three
  `Work`, three `Email` and three `Snippets` folders, and 6 extra outbox entries.
- Fix: reuse a live folder with the same parent and name and a tag with the same name, as the CSV
  path does; create a folder only when a snippet is written into it or below it. Add a re-import
  test.

### 10. Duplicate check of `choice` options is quadratic — medium, demonstrated

- Where: `crates/iamb-core/src/template/parse.rs:365-368`.
- What: each option is compared with all earlier ones. It runs at parse, so on every snapshot
  build and every editor parse, not on the typing path.
- Shown by: 10,000 options (59 KB body) parse in 0.14 s; 30,000 in 0.84 s; 60,000 (409 KB) in
  4.5 s.
- Fix: use a hash set. Consider a body size limit in the store; none exists today.

### 11. CSV export fails as a whole on one unusual folder or tag name — low, demonstrated

- Where: `crates/iamb-store/src/transfer.rs:596-620`.
- What: a folder name that contains ` / `, is empty or has surrounding spaces, or a tag name with
  `;`, aborts the export. The store accepts such names, and JSON import creates them.
- Shown by: a folder renamed to `R / D` in a JSON file, imported, then `iamb export out.csv` →
  exit 1 "cannot be written to CSV"; JSON export works.
- Fix: escape the separators in CSV, or validate names where they are created.

### 12. The store and the matcher fold case differently — low, demonstrated

- Where: `crates/iamb-core/src/model.rs:368` (`str::to_lowercase`, context-sensitive final
  sigma), `crates/iamb-core/src/matcher.rs:277` (per character, `ς` → `σ`).
- What: the store accepts two abbreviations that the matcher treats as one; the second can never
  fire and nothing says so when it is added.
- Shown by: `iamb add ΟΔΟΣ first` and `iamb add οδοσ second` both succeed; `iamb expand "οδοσ "`
  prints `first`.
- Fix: one folding function in `iamb-core`, used for `fold_key` and the matcher; a migration to
  recompute `abbreviation_key`.

### 13. Word-start context is lost where the engine could know better — low, demonstrated

- Where: `crates/iamb-core/src/engine.rs:416-434` (Backspace on an empty buffer),
  `engine.rs:613-620` and `680-688` (buffer cleared after a failed expansion).
- What: after Backspace removes a character the buffer does not hold, or after an expansion fails
  and leaves the abbreviation on screen, the buffer is empty and counts as a word start.
- Shown by: `brb ` expands, Backspace removes the space, `ty ` then expands directly after
  `back` (`be right backthank you `). `dr` (immediate, fails with `E_DATE_RANGE`) followed by
  `ty ` gives `drthank you `. Session `021_backspace_past_start.toml` asserts the first case.
- Fix: in both cases mark the buffer as having an unknown prefix (the `truncated` flag), so the
  start does not count as a boundary.

### 14. Form values are not checked against the form — low, demonstrated

- Where: `crates/iamb-core/src/template/render.rs:157-161`.
- What: a `choice` value outside its options, a `toggle` value other than `yes` or `no`, and a
  `text` value with a line break are accepted and typed.
- Shown by: options `S|M|L` with value `XXL` → typed `XXL`; toggle value `maybe` makes
  `{if … is=maybe}` true; a two-line value is typed into a one-line field.
- Fix: validate in `Engine::on_submitted` and drop the expansion with a diagnostic, or replace the
  bad value with the default.

### 15. The command-line tool splits folder paths on any `/` — low, demonstrated

- Where: `crates/iamb-cli/src/commands/folders.rs:15-17`; CSV uses ` / ` only.
- Shown by: CSV import creates one folder `TCP/IP`; `iamb add … --folder "TCP/IP"` creates `TCP`
  with a sub-folder `IP`; `iamb list --folder "TCP/IP"` cannot show the imported folder.
- Fix: split on ` / ` as the help text says.

### 16. The data directory and `library.db` are created readable by other users — low, demonstrated (Linux)

- Where: `crates/iamb-store/src/lib.rs:312-315`.
- Shown by: after `iamb add`, the directory is `drwxr-xr-x` and `library.db` is `-rw-r--r--`
  (umask 022). The threat model in architecture §8 includes other users on the machine.
- Fix: create the data root and `run/` with mode `0700` on Unix.

### 17. Durability on macOS is weaker than the code comment claims — low, suspected

- Where: `crates/iamb-store/src/lib.rs:336-345`.
- What: `synchronous = FULL` uses an ordinary `fsync` on macOS, which does not force the drive to
  write. The comment promises safety on power loss. Not testable on Linux.
- Fix: also set `PRAGMA fullfsync = ON` (and `checkpoint_fullfsync`) on macOS, or soften the
  comment.

### 18. Two things Phase 2 needs from the engine are missing — low, suspected (design)

- Where: `crates/iamb-core/src/engine.rs:388-394`, `crates/iamb-core/src/matcher/buffer.rs:31-34`.
- What: (a) the injector must type again the `k` characters typed after the trigger (§4.6), but
  the engine only counts them and no API returns them, so a second copy of typed characters
  would have to live outside the buffer, against §8 rule 1; (b) the buffer is boxed, but nothing
  lets the service lock that memory (`MemoryLock::lock(region)`).
- Fix: decide both before task 2.2, for example an action that carries the characters wrapped in
  `Sensitive`, and a method that hands the buffer's address range to a callback.

### 19. The architecture document lags behind the code — low, demonstrated

### 20. Weak or missing tests — low, demonstrated

- `crates/iamb-cli/src/session.rs:45-60`: the per-OS default data directories (`HOME`, `APPDATA`,

### 21. Smaller points in the command-line tool — low

- `crates/iamb-cli/src/commands/expand.rs:30`: a `--field` argument without `=` is echoed whole

## 5. Checked, no findings

- Template language: 166 examples; 130,000 generated templates compared with
  `spec/template/reference.py` on error code, actions, form and `cursor_back`. One difference, in
  the reference: it joins a combining mark to a preceding tab, which UAX #29 does not; the Rust
  result is the correct one.
- Parse, resolve and render error phases; cycle and depth checks with shared bodies; field
  merging and implicit toggles; cursor counting; line-ending normalisation; verbatim ranges.
- Date math: month ends, leap years, year range, 12-hour clock, locales (through the reference
  comparison and the table tests).
- Matcher: triggers, delimiters, case modes, folding that changes length, longest match, tie
  between immediate and delimiter, shadowing report, duplicates.
- Engine: suspension on focus, secure state, composition and pause; nothing stored while
  suspended; the injection state machine (pending, injecting, cancelled, lost markers, overflow);
  one form session at a time; clock and clipboard read once at the match; adaptive case leaves
  verbatim ranges alone; delimiter typed again except after a rendered cursor.
- Privacy: `KeyBuffer`, `Sensitive`, `Event`, `Action`, `FormValues`, `RenderContext`, `Rendered`
  and `Diagnostic` print no typed text, value or clipboard content; no `Serialize` on any of
  them; the buffer is zeroed on clear and on Backspace; diagnostics name only snippets and apps;
  template errors carry codes and positions only.
- Panics: no `unwrap`, slice or index in the three crates is reachable with bad input, apart from
  the documented trie limit of `u32::MAX` nodes. Arithmetic on dates, waits and counters is
  checked or saturating.
- Store: put, get, list, soft delete, folder cascade, outbox entry in the same transaction and
  rollback with it, uniqueness per profile with a unique index behind the check, folder depth and
  cycles on insert and move, purge order, migrations (forward only, newer schema refused), lock
  file taken before the database opens and released after it closes, recovery after a killed
  writer.
- Import and export: JSON and CSV round trips of the fixture library, malformed files rejected
  with nothing written, byte-order mark and CRLF accepted, unterminated quotes caught.
- Cross-platform: file locking uses the standard library on all three systems; the kill test
  uses a portable process kill; output and fixtures use LF with `.gitattributes` enforcing it;
  the data root follows architecture §3.3. Risks found are findings 16, 17 and the timing bound
  in 20.
